Cinq audits ont précédé celui-ci (25 et 26 septembre, 4 et 8 octobre).
Depuis le dernier, l'outil a gagné un onglet de boîtes dressées, un mode
opératoire illustré, six ordres de tri et un rangement à la main, le
choix de plusieurs postes dans les écarts, un retour aux réglages

tous les champs d'organisation livrés d'office et tous les tirets
cadratins. Dix-huit révisions, 84 fichiers touchés. **Un audit ne se
reconduit pas : il se refait.**

**Méthode.** La même qu'en octobre, plus une étape. Rien n'est accordé au
code sur la foi de ce qu'il déclare, et rien n'est repris d'un audit
précédent sans être remesuré. Les dépendances sont lues dans l'arbre
syntaxique ; les interdits sont constatés par une sonde d'exécution
(PEP 578) sur un parcours complet ; le livrable Windows est interrogé tel
qu'il s'installe. L'étape ajoutée : **une revue de code de toute la
semaine**, révision par révision, à la recherche des défauts que les
essais n'avaient pas vus. Elle en a trouvé quinze (§2). Tous sont
corrigés dans la révision auditée, chacun pinglé par un essai, et chaque
correction a été mise à l'épreuve d'une mutation du code qui la défait :
onze mutations, onze attrapées.

## 9. Ce que cet audit ne couvre pas

- **La signature Authenticode.** Le binaire n'est pas signé : SmartScreen
  avertira au premier lancement. Un certificat de signature de code est une
  décision de l'entreprise, pas de l'outil.
- **Le poste lui-même.** L'outil lit le fichier qu'on lui donne et écrit où
  on lui dit.
- **Le classeur Excel**, qui emporte les données individuelles et, si on le
  lui demande, une copie du fichier source. C'est sa raison d'être, refaire
  chaque calcul, documentée dans `DOSSIER-RSSI.md` §8.1.
- **La revue de code** a porté sur les dix-huit révisions de la semaine,
  pas sur l'ensemble du dépôt : ce qui n'a pas bougé depuis le 8 octobre
  reste couvert par les audits précédents.
